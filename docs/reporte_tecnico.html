1. Resumen Ejecutivo y Stack Tecnológico

GastOS es una aplicación móvil Android desarrollada bajo arquitectura por capas (UI declarativa con Jetpack Compose Material 3, capa de repositorio, persistencia local cifrada con Room + SQLCipher y consumo de servicios Web REST para autenticación y sincronización con Supabase).

Requisito Técnico Implementación en GastOS Archivos Clave
Persistencia local & CRUD Room 2.7.2 + SQLite cifrado con SQLCipher 4.6.1, 3 entidades relacionadas con llaves foráneas. AppDatabase.kt, GastoDao.kt, PresupuestoDao.kt, CategoriaDao.kt
Servicios Web & Auth Supabase Auth (signup, token, logout) y PostgREST con Retrofit 2.11.0 + OkHttp 4.12.0 + estados Loading/Success/Error. SupabaseApi.kt, NetworkModule.kt, AuthRepository.kt
Sensores & Multimedia Captura de fotos de tickets con cámara (TakePicture + FileProvider + Coil) y autenticación biométrica (BiometricPrompt). ExpenseFormDialog.kt, BiometricAuthHelper.kt
Notificaciones Locales NotificationCompat + WorkManager al superar ≥ 80% del presupuesto semanal/mensual. BudgetNotifier.kt, BudgetCheckWorker.kt
Seguridad Android KeyStore AES-256-GCM, SQLCipher AES-256, InputValidator y redacción de cabeceras JWT. CryptoManager.kt, SecureTokenStorage.kt, InputValidator.kt
Librerías de Terceros Vico Charts (compose-m3), Coil (coil-compose), Retrofit/OkHttp y SQLCipher. DashboardScreen.kt, ExpensesScreen.kt, gradle/libs.versions.toml

4. Mecanismos de Seguridad Implementados

Capa de Seguridad Mecanismo Técnico Propósito
Cifrado de Base de Datos SQLCipher 4.6.1 mediante SupportOpenHelperFactory con clave aleatoria de 32 bytes. Protege el archivo completo gastos_seguros.db en almacenamiento interno frente a extracción física o root.
Gestión de Llaves (Hardware) AndroidKeyStore con algoritmo AES/GCM/NoPadding (256 bits) e IV aleatorio por cifrado (CryptoManager). La clave maestra nunca abandona el entorno seguro del sistema operativo; cifra notas privadas, tokens y la passphrase de SQLCipher.
Manejo Seguro de Tokens SecureTokenStorage cifra accessToken y refreshToken, valida expiración (expiresAtEpochSec), y OkHttp aplica redactHeader("Authorization") y redactHeader("apikey"). Evita exposición de JWT en preferencias en texto plano o en registros Logcat durante depuración.
Validación y Saneamiento InputValidator valida correos RFC, contraseñas robustas (≥8 chars, mayúscula, minúscula y dígito), montos (0.01–999,999.99) y bloquea patrones <script, javascript: y DROP TABLE. Mitiga errores de captura, desbordamientos numéricos e inyecciones de código en formularios.
Biometría y Backup BiometricPrompt (BIOMETRIC_STRONG | WEAK | DEVICE_CREDENTIAL) y android:allowBackup="false" en AndroidManifest.xml. Previene respaldo no cifrado por ADB y protege la reapertura de sesión en el dispositivo.

5. Control de Versiones y Pull Request

Flujo Git implementado:
  • Ramas activas: main, develop, feature/login, feature/expenses-crud, feature/charts-notifications y hotfix/input-validation.
  • Pull Request documentado: Fusión de feature/login hacia develop con revisión técnica en docs/PR_REVIEW_feature_login.md.
  • Hotfix en producción: Corrección en hotfix/input-validation desde main y fusionada en main y develop.
